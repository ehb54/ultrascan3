Manual

SOMO - SAXS/SANS (SAS) Module: Data Utility (Buffer subtraction, joining and averaging)

Last updated: November 2026

Overview

The Data Utility module (window title US-SOMO: SAXS: Data Utility) is opened from the Data button in the I(q) panel of the SAS module. It is a general-purpose workbench for I(q) vs. q curves that are not part of a chromatography or kinetics run (for time-resolved data see the HPLC/KIN module instead). It provides:

  • Buffer (and blank/capillary) subtraction, with either a directly specified scaling factor or one computed from the solute partial specific volume and concentration, with full propagation of the standard deviations, and the buffer division, which shows how well a buffer matches a solution;

  • Joining of two curves measured over different q ranges (for example a small-angle and a wide-angle detector configuration, or two different sample-to-detector distances) into a single curve, with interactive scaling and an automatic scaling fit;

  • Averaging, concentration-normalized averaging, concentration normalization and weighted summation of sets of curves;

  • Checking dilutions: the concentrations a series' intensities imply, compared with the stated ones;

  • Upturn correction: fitting and subtracting a low-q upturn from large scatterers;

  • Buffer frames of a SEC-SAXS run: the I(t) of the frames, to choose stable buffer frames to average and subtract;

  • Cropping and trimming tools to bring curves onto a common q grid, remove unreliable low- or high-q points, or drop non-positive intensities;

  • Bookkeeping of concentrations, of the curves produced, and of what has and has not been written to disk.

Curves already plotted in the SAS module I(q) panel are handed over to the Data Utility automatically each time it is opened. They arrive in both the Data files and the Produced Data lists, since they do not yet exist on disk as far as this module is concerned, and any character that is awkward in a file name (whitespace, quotes, slashes, periods) is replaced by an underscore. Each curve keeps the concentration the SAS module holds for it, and its PSV and I(0) standard error when these differ from the SAS defaults (a curve that never had them is not given the defaults as if they were measured). A curve sent back keeps its concentration, PSV and I(0) standard error, and takes the defaults only for those it does not have. Conversely, any curve held in the Data Utility can be sent to the I(q) panel with the To SAS button.

Opening the module brings up the main window described below. The buffer subtraction controls are in a small companion window titled US-SOMO: SAXS: Data Utility : Fitting, opened with the Adv. buffer subtraction button (it is no longer opened together with the main window). The companion window stays above the main window, and closing the main window closes both.

Loading data

The upper left panel is labeled Data files. Above the list, the current working directory is shown; clicking on it opens a directory navigator. Checking the Lock checkbox next to it keeps that directory as the default instead of following whichever directory you last loaded from.

  • Add files opens a file selector. Recognized extensions are .dat, .int, .txt and .ssaxs; any other extension is refused with a message. Files are read as whitespace-separated columns, with the first column q, the second I(q) and, if present, the third the standard deviation. Lines beginning with # and lines that are not purely numeric are skipped, so most headers are handled automatically. The first line is taken as the file's header unless it holds data: a numeric line followed by one of larger q is read as the first point, so a file without a header line keeps its first point. When several files are selected at once they are re-ordered by any trailing numeric fields in their names, so that ..._2 sorts before ..._10.

    Note the following behavior while reading:

    • reading of a file stops at the first point whose q is not larger than the previous one, which conveniently truncates files that contain several concatenated blocks;

    • points with I(q) exactly zero are dropped;

    • a standard deviation column is used only if every point has a positive standard deviation. If any value is zero or negative, all of the standard deviations are discarded and a notice is issued in the Messages area. This matters, because most of the operations below propagate errors only when errors are present on all the curves involved;

    • a file whose name is already in the list is not loaded a second time. Curves are identified throughout the module by their base name, without directory or extension.

  • For .dat files, the first line is additionally scanned for the keywords Conc:, PSV:, I0se: and Units:. The concentration (in mg/ml), partial specific volume and I(0) standard error found there are attached to the curve and are carried through the operations below; the concentration also pre-fills the Concentrations table. Units: may be 1/A (or A^-1) or 1/nm (or nm^-1); q is converted to A-1 accordingly. When no Units: keyword is present, the conversion is taken from the q scale set in the SAS options, and a reminder is printed whenever that default is 1/nm.

  • Similar, active when exactly one curve is selected, looks at the disk file that curve came from, turns every run of two or more digits in its name into a wildcard, and loads every not-yet-loaded file in the same directory matching that pattern. This is the quickest way to pick up a whole series of exposures after having loaded one of them.

  • The RL (regular expression load) button with its two adjacent fields loads by pattern. The first field holds one or more printf-style patterns containing %1, the second a list of values to substitute. Every combination is expanded into a regular expression, and all matching files in the current directory are loaded. For example a pattern of lysozyme_%1_.*\.dat with arguments 001 002 003 loads the three corresponding series.

  • Concentrations opens the Solution Concentrations window.

  • Remove files removes the selected curves from the module. If any of them were produced here and not yet written to disk, you are offered the chance to save them first.

Selecting and displaying curves

Curves are selected in the Data files list with the usual click, shift-click and control-click; the line below the list reports how many of how many are selected. Every selected curve is plotted in the graph on the right. The buttons immediately below the list are:

  • Select all and Invert act on the whole list.

  • Select opens the Select curves dialog (active when more than two curves are loaded), which can select every Nth curve within a range of list positions, select by a substring of the name, or select by total integrated intensity above or below a threshold, with a preview plot to help place that threshold. It is described here.

  • To SAS copies the selected curves into the SAS module I(q) panel, together with their concentrations, for Guinier analysis, P(r) computation, fitting and so on.

  • View, active for up to ten selected curves, opens each of them in a text window showing the same columns that would be written to disk.

  • Log X / Lin X and Log Y / Lin Y switch the corresponding plot axis between linear and logarithmic scaling. Each button names the scale a click switches to; the plot starts with a linear q axis and a logarithmic intensity axis, so the buttons first read Log X and Lin Y.

  • Color rotates the plot colors, which is useful when many curves are displayed and two adjacent ones happen to receive similar colors.

  • Rescale resets the plot limits to the extent of the selected curves and clears any zoom.

  • Legend, below the plot, toggles the curve legend; it is disabled when more than twenty curves are selected, where a legend would be unreadable.

  • Err, below the plot, shows the standard deviations of the plotted curves as bars; on a logarithmic intensity axis, only the bars that stay positive are drawn. The bars are not listed in the legend.

The plot supports rubber-band zooming with the left mouse button, and the resulting zoom rectangle is what several of the cropping tools act upon.

Averaging, summing and normalizing

The next row of buttons combines the selected curves. All of them require the curves to be on the same q grid: the number of points must match after the automatic cropping described below, and corresponding q values must agree to within 5×10-6 A-1. If the selected curves have differing numbers of points they are first truncated to the shortest one, with a notice in the Messages area; if the q values themselves disagree, the operation is refused and you should use Crop Common first.

  • Average (active with two or more curves selected) forms the mean of the selected curves. If every selected curve carries non-zero standard deviations throughout, the mean is weighted by 1/σ2, and its standard deviation is that of the weighted mean, propagated from the curves' own, σ = 1/√(Σ 1/σi2): for n curves of equal σ, σ/√n, as in HPLC/KIN. The Messages area then also reports the reduced χ2 of the curves about their mean, Σ (Ii − <I>)2/σi2 divided by n − 1 and by the number of points. It is about 1 when the curves agree within their standard deviations, and well above 1 when they differ by more than that, e.g. through drift or radiation damage. Otherwise a plain unweighted mean is used, and its standard deviation is estimated from the scatter of the curves, their sample standard deviation divided by √n; with few curves this estimate is itself very uncertain. Which of the two was applied is always stated in the Messages area.

    Right-clicking Average (or Concentration normalized average, while the button is active) opens a menu with two options, which apply to both buttons and to the averages made in the buffer subtraction window, are remembered, and are described in the buttons' tooltips:

    • sd of the mean from the curves' scatter, instead of the default sd of the mean propagated from the curves' own sd: at each q the propagated standard deviation is multiplied by the square root of that point's reduced χ2, so that it becomes √(Σ wi (Ii − <I>)2 / ((n − 1) Σ wi)), the sample standard deviation divided by √n for curves of equal σ. This also includes variation the curves' own standard deviations do not, such as drift, but with few curves it is very uncertain. The saved header then says sd of the mean from their scatter instead of sd of the mean propagated from their sd, and the name of the result has avgs instead of avgp (see names).

    • Leave out spikes, with Spike threshold... (6 by default): at each q, the curve whose point is farthest from the weighted mean of the other curves, in standard deviations of their difference, is left out of that point's average if it is more than the threshold away; this is repeated while three or more curves remain. It needs standard deviations on every curve, and relies on most of the curves being free of a spike at each q: where most of them have one, the test cannot tell the spikes from the others. The points left out, per curve, are listed in the Messages area. Their number and the frames (or curves) they came from are written into the saved header, and a d is added to the name's code (avgpd, avgsd).

    The saved header of an average lists the averaged curves: when their names are numbered frames, as ranges of frame numbers with any gaps (e.g. frames 00104-00110,00115) rather than every name. It also says which standard deviation the average has. The concentration of the result is the mean of those of the contributing curves; its PSV and I(0) standard error are the means over the contributing curves that have one.

  • Concentration normalized average divides each curve by its own concentration before averaging, and then re-multiplies the result by the mean concentration. This is the correct way to average exposures of the same sample taken at slightly different concentrations, and it becomes active only when every selected curve has a non-zero concentration. With standard deviations, each normalized curve Ii/ci is weighted by 1/(σi/ci)2, so that the curves at higher concentration, whose normalized curves are less noisy, count more. The standard deviation, the reduced χ2 and the right-click options follow those of Average for the normalized curves, and the standard deviation is multiplied by the mean concentration like the curve. The PSV and I(0) standard error of the result are taken as for Average.

  • N (normalize) produces, for each selected curve, a copy divided by its own concentration; the standard deviations are divided by the same factor and the concentration of the result is set to 1; the PSV and I(0) standard error are kept. Like the previous button, it requires all the selected curves to have a non-zero concentration.

  • WS (weighted sum) prompts for a multiplier for each selected curve in turn and forms the weighted sum. Its standard deviation adds those of the weighted curves in quadrature, √(Σ wi2 σi2), as for independent measurements. Its concentration is the sum of each curve's multiplier times its concentration, and its PSV and I(0) standard error are taken as for Average. This button is only shown when the advanced configuration expert mode is enabled.

The buffer and the blank, if assigned, are excluded from Concentration normalized average and N.

The row below holds Check dilutions, Upturn corr and Adv. buffer subtraction, which opens the buffer subtraction window (or brings it to the front).

Checking dilutions

Check dilutions (active with two or more curves selected, other than the buffer and the blank) checks a dilution series against its stated concentrations, before any further processing. Where interparticle interactions play no role, the curves of a series should scale with their concentrations; an error in a concentration (or in the intensity normalization) shows up as a ratio between two curves that differs from the ratio of their concentrations by the same factor at every q. If the concentrations were measured independently (e.g. by UV absorbance) and still disagree with the intensities, something other than the dilution is wrong.

The window lists the selected curves, most concentrated first, with their stated concentration: the value in the Concentrations table or, when that is blank, the Conc found in the file header (the Stated from column says which). Where there is none the cell is red: double-click it and type the theoretical value, which is then shown next to the revised one. Any stated value can be changed the same way. Each curve's intensity is fitted over the chosen q range as ratio × reference + offset, the curve being interpolated onto the reference's q points. With standard deviations on both curves, the line is fitted with the errors of both taken into account (York et al., Am. J. Phys. 72, 367 (2004)), each point weighted by 1/(σcurve2 + ratio2 σreference2): a noisy reference, such as a dilute curve, does not bias the ratios, and fitting the reference to a curve gives the inverse of fitting the curve to the reference. The table gives the ratio with its standard error (enlarged by the square root of the reduced χ2 when that is above 1), the revised concentration (ratio × the reference's concentration) and its difference from the stated one, the offset and the reduced χ2.

  • Reference: the curve whose concentration is taken as correct; by default the most concentrated. The intensities fix only the ratios between the curves: all the revised concentrations, and so any molecular weight computed from them, scale with the reference's concentration. Choose the curve whose concentration is best known (e.g. measured by UV absorbance); any curve of the series can be the reference.

  • Fit over q from ... to: by default from 0.15 A-1 (or the upper half of the common q range when it ends below 0.2 A-1) to the end of the q range all the curves cover. Choose a range where interactions play no role and the curves are above the noise.

  • Check range: the same fit over a second range, by default from 0.03 A-1 to the start of the fit range (leave it empty for none). When a curve's ratio over the check range differs from its ratio over the fit range by more than 2% plus three standard errors, the two cells are shown in red: the difference between that curve and the reference depends on q, so over the check range it is not just the concentration (interactions, aggregation, a subtraction problem). The revised value, from the fit range, is still offered. When most curves are flagged, the reference itself probably shows interactions over the check range: a concentrated reference often does, without affecting the high-q ratios.

  • Offset: also fit a constant offset (on by default), e.g. for a small error in the buffer subtraction.

Use revised chooses, for each curve, which concentration goes with it: checked, the revised one; unchecked, the stated one. Make the new series lists the choices, asks for confirmation, and adds a copy name_dc of each curve to the Produced Data: its intensities unchanged, its concentration the chosen one (in the Concentrations table, and in the file header once saved with Save), and a header line saying where the concentration came from. The original curves are not changed. After changing a concentration, the reference or the ranges, press Fit again.

Upturn correction

Upturn corr (active with one or more curves selected, other than the buffer and the blank) removes from each selected curve a low-q upturn caused by a small amount of large scatterers (aggregates, or a contribution of the measurement).

Each curve is fitted on its own, from its first point (or the q set in Fit from q) up to the end of the solute's Guinier range, with

I(q) = G exp(−q2Rg2/3) + Ga exp(−q2Ra2/3) + Ba exp(−q2Rg2/3) [erf(q Ra/√6)3/q]P

a Guinier term for the solute (I(0) G, radius of gyration Rg) plus a Beaucage unified level for the large scatterer (radius of gyration Ra, power-law slope P between 1 and 4.5, the power law cut off at the solute's size). The fit ends at q = 1.3/Rg (the factor can be changed), iterated as Rg is refitted; it is a Levenberg-Marquardt least squares weighted by the curve's standard deviations, started from several large-scatterer sizes and slopes.

A curve has an upturn when the large-scatterer term at its first point is above three standard deviations of the data and above 5% of the solute term; a curve without one is left unchanged. For a curve with an upturn:

  • the term is subtracted below the q from which it stays under 0.5 standard deviations of the data (the factor can be changed), and at least up to the end of the fit; above that point, the splice, the curve is unchanged;

  • the standard deviations of the corrected points include the uncertainty of the subtracted term, propagated from the fit;

  • where the term is more than 0.25 times the solute's fitted intensity (the factor can be changed), the corrected intensity depends too much on the assumed shape of the term to be trusted (orange in the plot). When the copies are made, a question lists these points for each curve and offers to cut them from the corrected copies or keep them, corrected and noted in the header.

The table lists, for each curve, the fit range, the solute's I(0) and Rg, the large scatterer's Rg and slope, the reduced χ2, the q from which the correction is reliable and the q below which the term is subtracted. The plot shows the curve chosen above it (or clicked in the table) with the fit, its two terms and the corrected curve, and marks the end of the fit, the reliable limit and the splice. Make corrected copies adds a copy name_upc of each curve with an upturn to the Produced Data, with the curve's concentration, PSV and I(0) standard error, and a header line saying what was subtracted.

Buffer frames of a SEC-SAXS run

In a SEC-SAXS run the frames recorded before the void volume, before the first elution, are buffer, and so are often those after the signal has returned to baseline. Buffer frames, to the left of Set buffer and active with three or more curves selected, opens a window (US-SOMO: SAXS Data Utility : Buffer frames) that helps choose them among the selected frames:

  • The upper plot shows I(t): each frame's mean intensity over the q range set at the top (by default from the lowest q to 0.05 Å-1, where the elution of the sample shows first), against its frame number. The frames are ordered by the number in their names; when the names are not numbered frames, by their position in the selection. The I(t) is only shown here: nothing is added to the Data Utility. Log Y / Lin Y switches the intensity axis, and the plot zooms with the left mouse button; the cursor's position is shown in red.

  • The buffer frames before the elution are set by their first and last frame numbers (green dashed markers). With After the elution checked, a second region can be set (cyan markers). After clicking one of the four frame fields, the wheel and the < and > buttons move its marker frame by frame.

  • Next to each region's frame fields, Average, SD and chi^2 give, as the region changes, the average of its frames' I(t) (weighted by w = 1/σ2 when the frames have standard deviations, as the Average of the curves is), the standard deviation of their I(t) about that average, √(n Σ w (I(t) − average)2 / ((n − 1) Σ w)), which is the scatter of one frame's I(t) and the sample standard deviation when the σ are equal or absent, and the reduced χ2 of I(t) about the average, Σ ((I(t) − average) / σ)2 / (n − 1), about 1 when I(t) is flat within its standard deviations (empty when the frames have none).

  • Suggest, also run when the window opens, proposes the regions. The baseline level and noise of I(t) are estimated as their median and 1.4826 times their median absolute deviation (at least the frames' own I(t) standard deviation), first over the first fifth of the frames and then over the suggested region. The elution starts where I(t) is more than 3 noise standard deviations above the baseline for three frames in a row; the region before it ends three frames earlier and extends back while I(t) stays within 4 standard deviations of the baseline. After the largest peak, the second region starts two frames after I(t) is back within 4 standard deviations of the baseline for good, if it is; otherwise only the first region is suggested. Check the suggestion on the plots, and adjust it as needed.

  • For each region, the text below the plots gives its frames, the mean of I(t), the drift of I(t) across it from a straight line fitted to it (drawn in the region's color; weighted by 1/σ2 when the frames have standard deviations) with its standard deviation, and the reduced χ2 of I(t) about that line. When every frame has standard deviations and all are on one q grid, each frame of a region is compared, over its whole curve, with the 1/σ2-weighted mean of the region's other frames: χ2 = Σ (Ik − <I>others)2 / (σk2 + σ2others), divided by the number of points. The lower plot shows these values; they are about 1 for frames that agree with the others within their standard deviations. Frames above the 0.1% limit of that χ2 (red dashed line) are listed, and marked red on the I(t) plot. With both regions set, their average curves are compared in the same way, and the ratio of their mean I(t) is given: whether the buffer after the elution matches the one before it.

  • With both regions set, a straight line is also fitted to the I(t) of the frames of both regions (weighted as above) and drawn red and dashed from the first to the last of them. The text gives its change across them, in percent of its value at the first, with its standard deviation, and the reduced χ2 of I(t) about it next to those of each region about its own line. When the signal returns to its level before the elution, the line is flat. A steady drift tilts it, and each region drifts too, but it still fits both regions about as well as their own lines do. When the signal does not return to baseline, the line rises (or falls) across the elution while each region's own drift stays small, and its χ2 is larger than the regions' own: the more so, the larger the step is compared with the noise of I(t).

  • Select the frames before the elution and Select the frames of both regions select those frames, and nothing else, in the Data files list. Then Average makes the buffer average; select it and press Set buffer, then select the frames to subtract it from and press Subtract.

Assigning the buffer, blank and solution

Three buttons assign roles to a single selected curve; the assigned name is shown to the right of each button:

  • Set buffer — the matching buffer or solvent scattering. Subtract, to the right of its name, subtracts it from every selected curve (other than the buffer and the blank) point by point, with α = 1 and the standard deviations added in quadrature, as √(σ2curve + σ2buffer). Each result, named curve_bsub_a1, keeps the concentration, PSV and I(0) standard error of its curve; non-positive results are left as they are and counted in its header. The results share the buffer, so an Average of them understates its contribution, as explained under Processing many samples at once below. For a scaled buffer, a blank, or a range of values, use the buffer subtraction window.

  • Buffer frames, to the left of Set buffer, helps choose the buffer frames of a SEC-SAXS run to average (see Buffer frames).

  • Set blank — the empty cell, capillary or blank measurement. This one is optional; leave it unset for the usual two-curve subtraction.

  • Set solution — the sample from which the buffer is to be subtracted.

A curve already holding one of the three roles cannot be assigned another, so the three buttons grey out when a curve that already has a role is selected. Curves assigned as buffer or blank are excluded from the concentration table and from the normalization operations above.

Buffer subtraction

The subtraction itself is driven from the companion : Fitting window, opened with the Adv. buffer subtraction button. Its table holds three parameters and the radio buttons and checkboxes below it control what happens to the result.

The subtraction model

The quantity computed is

I(q) = Isolution(q) − α Ibuffer(q) − (1 − α) Iblank(q)

where the last term is present only if a blank has been assigned. The factor α accounts for the volume of buffer displaced by the solute: in a solution of concentration c, the buffer occupies slightly less than the full illuminated volume, so subtracting the full buffer signal over-subtracts. α can be supplied in either of two ways, and the table enforces that exactly one of them is active — checking PSV or Gamma automatically unchecks Alpha, and vice versa:

  • Alpha — α is used directly as given. The default range is 0.95 to 1. α = 1 is the plain, unscaled subtraction.

  • PSV together with Gamma — α is computed from the solute partial specific volume as

    α = 1 − γ c ψ / 1000

    with c the concentration of the solution curve in mg/ml (taken from the Solution Concentrations window) and ψ the partial specific volume in ml/g, default range 0.5 to 0.8. Gamma is an additional empirical scaling on that correction, default 1 and defaults ranging over 0.95 to 1.05; it lets you explore how sensitive the result is to the assumed volume displacement. A warning is issued if the solution has no concentration set, in which case α degenerates to 1.

The parameter table

Each row of the table has the columns Parameter, Active, Low value, High value, Points, Interval, Current value and Best value. Points and Interval are kept consistent with each other and with the low/high limits: editing either one recomputes the other. Current value is the value used by the single-shot buttons and is filled automatically while a range is being scanned.

Handling of non-positive results

Buffer subtraction is a difference of two nearly equal positive quantities, so at high q the result frequently goes to zero or below. The radio buttons labeled Buffer subtraction non-positive: decide what to do:

  • Crop (the default) truncates the curve at the first non-positive point. If that occurs within the first two points, nothing is produced and a notice is issued.

  • Set to minimum replaces every non-positive value with the minimum value found in the curve.

  • Ignore leaves the values as they are. Note that such a curve cannot be displayed on a logarithmic intensity axis.

  • Ask raises a dialog offering the same three choices for each subtraction; it therefore blocks unattended mass processing.

In every case the number of affected points and the q value at which the problem starts are reported in the Messages area.

Propagation of the standard deviations

Assuming zero covariance between the measurements, the standard deviations are combined as

σ2 = σ2solution + α2 σ2buffer + (1 − α)2 σ2blank

where each term is included only if that curve actually carries standard deviations. If the buffer or the blank has them but the solution does not, a warning is issued and the available ones are propagated alone.

Running the subtraction

  • Current value buffer subtraction performs a single subtraction with the values currently in the Current value column.

  • Buffer subtraction over range scans every active parameter from its Low value to its High value in Points steps, performing one subtraction at each combination and producing one output curve per combination. The total number of combinations is the product over the active rows, and is reported before the run starts. It can be interrupted with Stop.

  • Current value buffer divide forms the ratio Isolution(q) / [α Ibuffer(q)] instead of the difference. This is a diagnostic: a well-matched buffer gives a ratio that is flat and close to one over the region where the solute does not scatter. If a blank has been assigned, its (1 − α) term is subtracted from the ratio. The standard deviation is that of a ratio, σR2 = R2 [(σsolution/Isolution)2 + (σbuffer/Ibuffer)2] + (1 − α)2 σ2blank, where R = Isolution / (α Ibuffer).

Processing many samples at once

Checking Subtract buffer from every selected file (excepting those assigned as buffer and blank) makes all of the above act on every selected curve in turn rather than only on the one assigned with Set solution, using each curve's own concentration where the PSV method is active. This is the normal way to reduce a whole set of exposures in one step. Two further checkboxes then become available: Average and Concentration normalized average, which automatically apply the corresponding operation to the set of curves just produced.

The curves produced this way all contain the same buffer (and blank), so their noise is not independent: the buffer's is the same in each of them. The averages these two checkboxes make take this into account and count the buffer's and the blank's standard deviations once, so that the result's standard deviation combines that of the mean of the solutions with that of the buffer subtracted; the reduced χ2 reported is that of the solutions' own parts. An Average made afterwards from the produced curves with the button cannot know this, and treats them as independent, which understates the buffer's contribution: the standard deviation comes out about 1.3 times too small for 10 curves and a buffer averaged from 10 frames, and 2 times for a buffer averaged from 2. To average curves that share a buffer, use these checkboxes, or average the solutions first and subtract the buffer from their average; the averaged intensities are practically the same either way.

Joining two curves

Joining merges two curves covering different, partly overlapping q ranges — typically a small-angle and a wide-angle configuration of the same sample — into a single curve. Because the two measurements are generally on different arbitrary scales, one of them has to be brought onto the scale of the other before they are spliced together.

Select exactly two curves and press Join, below the plot. You are asked which of the two is the low-q curve. The two curves are then re-drawn in cyan (low-q) and yellow (high-q), the overlapping q interval is determined, and three vertical markers appear on the plot: Start and End in red, delimiting the overlap region, and Join point in magenta. The rest of the interface is disabled until the join is completed or abandoned. If the two curves do not overlap at all, the join is refused.

The row of fields below the plot then controls the join:

  • Linear offset and Multiplier are the constant b and the factor a applied to the curve being adjusted, as a I(q) + b. Standard deviations are scaled by a as well.

  • Start and End delimit the window, within the overlap, over which the two curves are compared — both by the automatic Fit and by the RMSD readout. Narrow it to exclude a part of the overlap you do not trust, such as the last few noisy points of the low-q curve.

  • Cut is the q value at which the two curves are spliced: the output takes the low-q curve up to and including this q, and the high-q curve beyond it. It need not coincide with a data point of either curve.

  • Scale low-q / Scale high-q swaps which of the two curves the offset and the multiplier are applied to; the button label always states what pressing it will do next. Swapping also inverts the current values (the offset changes sign and the multiplier is replaced by its reciprocal), so the relative adjustment is preserved.

  • The number at the right end of the row is the RMSD between the two curves over the Start to End window, and it updates whenever a parameter changes. It is the quantity to minimize.

Any of the five numeric fields can be adjusted with the wheel above them: click into a field to give it the focus and the wheel is bound to it, with a range appropriate to that quantity (the observed intensity range for the offset, 0.1 to 10 for the multiplier, the overlap interval for the three q values). The current wheel value is displayed to its left. The plot updates live, so you can bring the two curves onto each other by eye and watch the RMSD as you go.

Fit determines the multiplier automatically by a least-squares scaling fit of one curve onto the other over the Start to End window, weighted by the standard deviations when both curves have them, and sets the offset to zero. Linear would instead fit both a slope and an intercept (see Notes and current limitations).

Keep commits the join: a new curve is created, made of the low-q curve up to Cut followed by the high-q curve beyond it, with the offset and multiplier applied to whichever of the two is being scaled, and with standard deviations carried over when both curves have them. It has the concentration, PSV and I(0) standard error of the curve that is not scaled. The two source curves are deselected and the new one selected. Cancel abandons the join and restores the original display.

If a non-zero Linear offset is in effect when Keep is pressed, a reminder is displayed, quoting P. Vachette: this additional constant is to be avoided and if introduced, requires great care because it can hide an experimental problem which is thus swept under the carpet but could lead to erroneous interpretation. The offset is nevertheless applied if you proceed — the message is advice, not a refusal.

Cropping and trimming

The buttons in the row below the plot operate on the selected curves. The ones that depend on the visible region require the plot to be zoomed in; they are inactive at full zoom-out.

  • Select Visible reduces the selection to those curves that have at least one point inside the current zoom rectangle. With many curves loaded, zooming onto an outlier and pressing this button is the fastest way to identify it.

  • Remove Visible removes those curves from the module altogether (offering to save any unsaved produced curves among them first), and then zooms back out one step.

  • Crop Common reduces every selected curve to the q values common to all of them, which is the prerequisite for averaging and for buffer subtraction across data from different sources. q values that differ only in the last digits are treated as the same grid point — they are matched with a relative tolerance of 10-4, while the retained points keep their original q, I(q) and standard deviation. Without this, curves written with six significant figures can produce spurious holes in the common grid. The maximal and the common q ranges and their point counts are reported before anything is changed, and if the grids are already identical nothing is done.

  • Crop Visible reduces the selected curves to the q range currently visible. It refuses to cut the middle out of a curve, and it refuses a selection in which some curves would be cropped on the left and others on the right.

  • Crop Zeros removes every point whose intensity is not positive. A confirmation dialog first points out that noisy data with occasional negative values are physically meaningful, being the difference between two positive and very close intensities — removing such points biases the remainder upwards. Use it only where a logarithmic display or an external program leaves no alternative.

  • Crop Left and Crop Right remove points one at a time from the respective end of each selected curve. They work in two stages: if the end point in question is not visible in the current zoom, the first press pans and resizes the zoom rectangle so that the outermost few points are shown, and prints press again to crop one point; each subsequent press removes one point. This lets you watch exactly what you are discarding at the beam stop or in the noise at high q.

  • Undo reverses the cropping operations one at a time, in reverse order. The undo history covers Crop Common, Crop Visible, Crop Left and Crop Right.

Any loaded curve that is modified by one of the cropping tools is added to the Produced Data list, so that the modified version can be saved without overwriting your original data unintentionally, and a produced curve that a crop modifies is marked as not saved again. A curve that a crop leaves unchanged — one already on the common grid in Crop Common, for instance — keeps its state.

Produced Data and saving

Every curve created by the module — subtractions, divisions, joins, averages, normalizations and cropped copies — is added both to the Data files list, so it can be used as input to further operations, and to the Produced Data list below it. The directory to which produced curves will be written is shown above that list. It starts at the SOMO saxs directory and is then set to a subdirectory named produced under the directory you last loaded from, unless Lock is checked. Clicking on it opens a directory navigator, and the directory is created on the first save if it does not exist.

  • Select all selects the whole produced list.

  • Similar extends the selection to the curves whose names follow the same pattern as the first selected one — the whole family of subtractions from one parameter scan, for instance.

  • Save writes the selected produced curves that are not saved yet as individual files, and is active only while some of the selected ones are still unsaved. Each is written with the name of the file it originated from, or the curve name with a .dat extension; existing files raise an overwrite prompt with an overwrite all option. A saved curve is shown in grey italics in the Produced Data list, and its tooltip gives the file it was saved as; it is not saved again unless it changes.

  • Save CSV writes all the selected produced curves into a single comma-separated file, whose name is derived from the common part of their names. If their q grids are not identical, versions cropped to the common grid are included in the output for compatibility, and a notice is issued.

  • Show adds the selected produced curves to the plot, and Show only displays them and nothing else.

  • Right-clicking an entry in the Produced Data list makes a copy of it under a new name; the original stays. The copy keeps the concentration, PSV and I(0) standard error, and the description of how the curve was made (see below).

Individual files are written with a one-line header of the form

US-SOMO: SAXS: Data Utility output: name PSV:value I0se:value Conc:value Units:1/a description

followed by a column-heading line, q (1/Angstrom)  I(q)  sd, and the data as q, I(q) and, when available, the standard deviation. The PSV, I0se and Conc fields appear only when those quantities are known, and are read back when the file is loaded again, here or elsewhere in US-SOMO. Units:1/a states that q is in Å-1, whatever the units of the data it came from; it is read back too, so it keeps this exact form.

The description at the end of the header records how a produced curve was made:

  • buffer subtraction and buffer divide: the formula with the solution, buffer and blank and α; γ, the concentration and the psv when α is computed from them; and how non-positive points were handled, if there were any;
  • average and concentration normalized average: the number of files; the frames, as ranges of frame numbers, when their names differ only by a frame number, and otherwise the files themselves; the weighting and which standard deviation the average has; the points left out as spikes and the frames they came from; and any cropping (for the concentration normalized average, also the concentrations);
  • weighted sum: the files and their weights;
  • N normalization: the source curve and its concentration;
  • join and the interactive join: the two curves, the join point and, for the interactive join, the scaling and the offset.
For example:

US-SOMO: SAXS: Data Utility output: lyz_avgp_00010-00050 Conc:4.8 Units:1/a Average of 41 files (frames 00010-00050), weighted by 1/sd^2, sd of the mean propagated from their sd

Curves loaded from files have no description, and keep none when they are cropped and saved.

Closing the window while produced curves remain unsaved raises a dialog listing them (up to fifteen by name) and offering to save them, to close anyway, or to cancel the close.

Concentrations and the companion dialogs

The Concentrations button opens the Solution Concentrations window, a table of every loaded curve and its concentration in mg/ml. The buffer and the blank are excluded, and the table is kept in step with the file list as curves are added, removed and created. Concentrations found in .dat file headers appear there automatically, and curves produced by the module inherit an appropriate value — the concentration of the solution for a subtraction or a division, the mean for an average, 1 for a normalized curve, that of the curve that is not scaled for a join, and the sum of each curve's multiplier times its concentration for a weighted sum. The PSV and I(0) standard error are carried the same way: from the solution for a subtraction or a division, from the source for a normalized curve or a copy, from the curve that is not scaled for a join, and as the mean over the curves that have one for an average, a concentration normalized average or a weighted sum. They are written into the header of each saved curve. Concentrations are needed for the PSV route to α, for N and for Concentration normalized average, and are written into the header of each saved curve.

Values typed into that window take effect only once its Save values button has been pressed; a warning is issued if a calculation is started while edits are still pending. The window can be left open alongside this one.

The Data Utility has three companion dialogs, each with its own page in this manual:

  • Solution Concentrations — the concentration table itself, its copy and paste operations, and the loading and saving of .sbc concentration files.

  • File Concentration Loader — reached from Load in the above when the chosen file is not a .sbc file. It maps the columns of an arbitrary tabular file onto curve identifiers and concentrations, with a timecode adjustment and a trial match.

  • Select curves — reached from Select, for picking a subset out of a long list of curves by position, by name or by integrated intensity.

Notes and current limitations

  • The Best buffer subtraction button in the : Fitting window is not yet implemented and performs no action. Use Buffer subtraction over range and choose among the resulting curves.

  • The Guinier checkbox below the plot is not yet implemented. Guinier analysis is available in the SAS module I(q) panel; send the curves there with the To SAS button.

  • The Linear button in the join, which would fit an offset in addition to a multiplier, is currently disabled, in keeping with the caution against introducing a constant offset noted above.

  • The automatic Fit and the join itself require the two curves to share a common q grid over the fitted region; there is no interpolation. Where the two configurations were sampled differently, run Crop Common first.

  • Buffer subtraction, averaging and the related operations all require identical q grids, matched to within 5×10-6 A-1. The error message incompatible grids means either that the point counts differ or that the q values do; Crop Common resolves both.

  • Standard deviations are propagated only where all of the participating curves carry them (an average of curves without them gets one estimated from their scatter). Since a single non-positive standard deviation causes the whole error column of a file to be discarded on loading, an unexpected NOT using standard deviation notice is usually traced back to that.
