Manual

SOMO - SAXS/SANS (SAS) Module: Data Utility (Buffer subtraction, joining and averaging)

Last updated: September 2026

Overview

The Data Utility module (window title US-SOMO: SAXS: Data Utility) is opened from the Data button in the I(q) panel of the SAS module. It is a general-purpose workbench for I(q) vs. q curves that are not part of a chromatography or kinetics run (for time-resolved data see the HPLC/KIN module instead). It provides:

  • Buffer (and blank/capillary) subtraction, with either a directly specified scaling factor or one computed from the solute partial specific volume and concentration, with full propagation of the standard deviations;

  • Joining of two curves measured over different q ranges (for example a small-angle and a wide-angle detector configuration, or two different sample-to-detector distances) into a single curve, with interactive scaling and an automatic scaling fit;

  • Averaging, concentration-normalized averaging, concentration normalization and weighted summation of sets of curves;

  • Cropping and trimming tools to bring curves onto a common q grid, remove unreliable low- or high-q points, or drop non-positive intensities;

  • Bookkeeping of concentrations, of the curves produced, and of what has and has not been written to disk.

Curves already plotted in the SAS module I(q) panel are handed over to the Data Utility automatically each time it is opened. They arrive in both the Data files and the Produced Data lists, since they do not yet exist on disk as far as this module is concerned, and any character that is awkward in a file name (whitespace, quotes, slashes, periods) is replaced by an underscore. Conversely, any curve held in the Data Utility can be sent to the I(q) panel with the S button.

Opening the module brings up two windows: the main window described below, and a small companion window titled US-SOMO: SAXS: Data Utility : Fitting that holds the buffer subtraction controls. Closing the main window closes both.

Loading data

The upper left panel is labeled Data files. Above the list, the current working directory is shown; clicking on it opens a directory navigator. Checking the Lock checkbox next to it keeps that directory as the default instead of following whichever directory you last loaded from.

  • Add files opens a file selector. Recognized extensions are .dat, .int, .txt and .ssaxs; any other extension is refused with a message. Files are read as whitespace-separated columns, with the first column q, the second I(q) and, if present, the third the standard deviation. Lines beginning with # and lines that are not purely numeric are skipped, so most headers are handled automatically. When several files are selected at once they are re-ordered by any trailing numeric fields in their names, so that ..._2 sorts before ..._10.

    Note the following behavior while reading:

    • reading of a file stops at the first point whose q is not larger than the previous one, which conveniently truncates files that contain several concatenated blocks;

    • points with I(q) exactly zero are dropped;

    • a standard deviation column is used only if every point has a positive standard deviation. If any value is zero or negative, all of the standard deviations are discarded and a notice is issued in the Messages area. This matters, because most of the operations below propagate errors only when errors are present on all the curves involved;

    • a file whose name is already in the list is not loaded a second time. Curves are identified throughout the module by their base name, without directory or extension.

  • For .dat files, the first line is additionally scanned for the keywords Conc:, PSV:, I0se: and Units:. The concentration (in mg/ml), partial specific volume and I(0) standard error found there are attached to the curve and are carried through the operations below; the concentration also pre-fills the Concentrations table. Units: may be 1/A (or A^-1) or 1/nm (or nm^-1); q is converted to A-1 accordingly. When no Units: keyword is present, the conversion is taken from the q scale set in the SAS options, and a reminder is printed whenever that default is 1/nm.

  • Similar, active when exactly one curve is selected, looks at the disk file that curve came from, turns every run of two or more digits in its name into a wildcard, and loads every not-yet-loaded file in the same directory matching that pattern. This is the quickest way to pick up a whole series of exposures after having loaded one of them.

  • The RL (regular expression load) button with its two adjacent fields loads by pattern. The first field holds one or more printf-style patterns containing %1, the second a list of values to substitute. Every combination is expanded into a regular expression, and all matching files in the current directory are loaded. For example a pattern of lysozyme_%1_.*\.dat with arguments 001 002 003 loads the three corresponding series.

  • Concentrations opens the Solution Concentrations window.

  • Remove files removes the selected curves from the module. If any of them were produced here and not yet written to disk, you are offered the chance to save them first.

Selecting and displaying curves

Curves are selected in the Data files list with the usual click, shift-click and control-click; the line below the list reports how many of how many are selected. Every selected curve is plotted in the graph on the right. The buttons immediately below the list are:

  • Select all and Invert act on the whole list.

  • Select opens the Select curves dialog (active when more than two curves are loaded), which can select every Nth curve within a range of list positions, select by a substring of the name, or select by total integrated intensity above or below a threshold, with a preview plot to help place that threshold. It is described here.

  • C rotates the plot colors, which is useful when many curves are displayed and two adjacent ones happen to receive similar colors.

  • S copies the selected curves into the SAS module I(q) panel, together with their concentrations, for Guinier analysis, P(r) computation, fitting and so on.

  • View, active for up to ten selected curves, opens each of them in a text window showing the same columns that would be written to disk.

  • X and Y toggle the corresponding plot axis between linear and logarithmic scaling.

  • Rescale resets the plot limits to the extent of the selected curves and clears any zoom.

  • Legend, below the plot, toggles the curve legend; it is disabled when more than twenty curves are selected, where a legend would be unreadable.

The plot supports rubber-band zooming with the left mouse button, and the resulting zoom rectangle is what several of the cropping tools act upon.

Averaging, summing and normalizing

The next row of buttons combines the selected curves. All of them require the curves to be on the same q grid: the number of points must match after the automatic cropping described below, and corresponding q values must agree to within 5×10-6 A-1. If the selected curves have differing numbers of points they are first truncated to the shortest one, with a notice in the Messages area; if the q values themselves disagree, the operation is refused and you should use Crop Common first.

  • Average (active with two or more curves selected) forms the mean of the selected curves. If every selected curve carries non-zero standard deviations throughout, the mean is weighted by 1/σ2 and the standard deviation of the mean is computed accordingly; otherwise a plain unweighted mean is used. Which of the two was applied is always stated in the Messages area. The concentration, PSV and I(0) standard error of the result are the averages of those of the contributing curves.

  • Concentration normalized average divides each curve by its own concentration before averaging, and then re-multiplies the result by the mean concentration. This is the correct way to average exposures of the same sample taken at slightly different concentrations, and it becomes active only when every selected curve has a non-zero concentration.

  • N (normalize) produces, for each selected curve, a copy divided by its own concentration; the standard deviations are divided by the same factor and the concentration of the result is set to 1. Like the previous button, it requires all the selected curves to have a non-zero concentration.

  • WS (weighted sum) prompts for a multiplier for each selected curve in turn and forms the weighted sum. This button is only shown when the advanced configuration expert mode is enabled.

The buffer and the blank, if assigned, are excluded from Concentration normalized average and N.

Assigning the buffer, blank and solution

Three buttons assign roles to a single selected curve; the assigned name is shown to the right of each button:

  • Set buffer — the matching buffer or solvent scattering.

  • Set blank — the empty cell, capillary or blank measurement. This one is optional; leave it unset for the usual two-curve subtraction.

  • Set solution — the sample from which the buffer is to be subtracted.

A curve already holding one of the three roles cannot be assigned another, so the three buttons grey out when a curve that already has a role is selected. Curves assigned as buffer or blank are excluded from the concentration table and from the normalization operations above.

Buffer subtraction

The subtraction itself is driven from the companion : Fitting window. Its table holds three parameters and the radio buttons and checkboxes below it control what happens to the result.

The subtraction model

The quantity computed is

I(q) = Isolution(q) − α Ibuffer(q) − (1 − α) Iblank(q)

where the last term is present only if a blank has been assigned. The factor α accounts for the volume of buffer displaced by the solute: in a solution of concentration c, the buffer occupies slightly less than the full illuminated volume, so subtracting the full buffer signal over-subtracts. α can be supplied in either of two ways, and the table enforces that exactly one of them is active — checking PSV or Gamma automatically unchecks Alpha, and vice versa:

  • Alpha — α is used directly as given. The default range is 0.95 to 1. α = 1 is the plain, unscaled subtraction.

  • PSV together with Gamma — α is computed from the solute partial specific volume as

    α = 1 − γ c ψ / 1000

    with c the concentration of the solution curve in mg/ml (taken from the Solution Concentrations window) and ψ the partial specific volume in ml/g, default range 0.5 to 0.8. Gamma is an additional empirical scaling on that correction, default 1 and defaults ranging over 0.95 to 1.05; it lets you explore how sensitive the result is to the assumed volume displacement. A warning is issued if the solution has no concentration set, in which case α degenerates to 1.

The parameter table

Each row of the table has the columns Parameter, Active, Low value, High value, Points, Interval, Current value and Best value. Points and Interval are kept consistent with each other and with the low/high limits: editing either one recomputes the other. Current value is the value used by the single-shot buttons and is filled automatically while a range is being scanned.

Handling of non-positive results

Buffer subtraction is a difference of two nearly equal positive quantities, so at high q the result frequently goes to zero or below. The radio buttons labeled Buffer subtraction non-positive: decide what to do:

  • Crop (the default) truncates the curve at the first non-positive point. If that occurs within the first two points, nothing is produced and a notice is issued.

  • Set to minimum replaces every non-positive value with the minimum value found in the curve.

  • Ignore leaves the values as they are. Note that such a curve cannot be displayed on a logarithmic intensity axis.

  • Ask raises a dialog offering the same three choices for each subtraction; it therefore blocks unattended mass processing.

In every case the number of affected points and the q value at which the problem starts are reported in the Messages area.

Propagation of the standard deviations

Assuming zero covariance between the measurements, the standard deviations are combined as

σ2 = σ2solution + α2 σ2buffer + (1 − α)2 σ2blank

where each term is included only if that curve actually carries standard deviations. If the buffer or the blank has them but the solution does not, a warning is issued and the available ones are propagated alone.

Running the subtraction

  • Current value buffer subtraction performs a single subtraction with the values currently in the Current value column.

  • Buffer subtraction over range scans every active parameter from its Low value to its High value in Points steps, performing one subtraction at each combination and producing one output curve per combination. The total number of combinations is the product over the active rows, and is reported before the run starts. It can be interrupted with Stop.

  • Current value buffer divide forms the ratio Isolution(q) / [α Ibuffer(q)] instead of the difference. This is a diagnostic: a well-matched buffer gives a ratio that is flat and close to one over the region where the solute does not scatter. If a blank has been assigned, its (1 − α) term is subtracted from the ratio.

Processing many samples at once

Checking Subtract buffer from every selected file (excepting those assigned as buffer and blank) makes all of the above act on every selected curve in turn rather than only on the one assigned with Set solution, using each curve's own concentration where the PSV method is active. This is the normal way to reduce a whole set of exposures in one step. Two further checkboxes then become available: Average and Concentration normalized average, which automatically apply the corresponding operation to the set of curves just produced.

Joining two curves

Joining merges two curves covering different, partly overlapping q ranges — typically a small-angle and a wide-angle configuration of the same sample — into a single curve. Because the two measurements are generally on different arbitrary scales, one of them has to be brought onto the scale of the other before they are spliced together.

Select exactly two curves and press Join, below the plot. You are asked which of the two is the low-q curve. The two curves are then re-drawn in cyan (low-q) and yellow (high-q), the overlapping q interval is determined, and three vertical markers appear on the plot: Start and End in red, delimiting the overlap region, and Join point in magenta. The rest of the interface is disabled until the join is completed or abandoned. If the two curves do not overlap at all, the join is refused.

The row of fields below the plot then controls the join:

  • Linear offset and Multiplier are the constant b and the factor a applied to the curve being adjusted, as a I(q) + b. Standard deviations are scaled by a as well.

  • Start and End delimit the region of overlap used for the comparison of the two curves.

  • Cut is the q value at which the two curves are spliced: the output takes the low-q curve up to and including this q, and the high-q curve beyond it. It need not coincide with a data point of either curve.

  • Scale low-q / Scale high-q swaps which of the two curves the offset and the multiplier are applied to; the button label always states what pressing it will do next. Swapping also inverts the current values (the offset changes sign and the multiplier is replaced by its reciprocal), so the relative adjustment is preserved.

  • The number at the right end of the row is the RMSD between the two curves over the overlap, and it updates whenever a parameter changes. It is the quantity to minimize.

Any of the five numeric fields can be adjusted with the wheel above them: click into a field to give it the focus and the wheel is bound to it, with a range appropriate to that quantity (the observed intensity range for the offset, 0.1 to 10 for the multiplier, the overlap interval for the three q values). The current wheel value is displayed to its left. The plot updates live, so you can bring the two curves onto each other by eye and watch the RMSD as you go.

Fit determines the multiplier automatically by a least-squares scaling fit of one curve onto the other over the overlap, weighted by the standard deviations when both curves have them, and sets the offset to zero. Linear would instead fit both a slope and an intercept (see Notes and current limitations).

Keep commits the join: a new curve is created, made of the low-q curve up to Cut followed by the high-q curve beyond it, with the offset and multiplier applied to whichever of the two is being scaled, and with standard deviations carried over when both curves have them. The two source curves are deselected and the new one selected. Cancel abandons the join and restores the original display.

If a non-zero Linear offset is in effect when Keep is pressed, a reminder is displayed, quoting P. Vachette: this additional constant is to be avoided and if introduced, requires great care because it can hide an experimental problem which is thus swept under the carpet but could lead to erroneous interpretation. The offset is nevertheless applied if you proceed — the message is advice, not a refusal.

Cropping and trimming

The buttons in the row below the plot operate on the selected curves. The ones that depend on the visible region require the plot to be zoomed in; they are inactive at full zoom-out.

  • Select Visible reduces the selection to those curves that have at least one point inside the current zoom rectangle. With many curves loaded, zooming onto an outlier and pressing this button is the fastest way to identify it.

  • Remove Visible removes those curves from the module altogether (offering to save any unsaved produced curves among them first), and then zooms back out one step.

  • Crop Common reduces every selected curve to the q values common to all of them, which is the prerequisite for averaging and for buffer subtraction across data from different sources. q values that differ only in the last digits are treated as the same grid point — they are matched with a relative tolerance of 10-4, while the retained points keep their original q, I(q) and standard deviation. Without this, curves written with six significant figures can produce spurious holes in the common grid. The maximal and the common q ranges and their point counts are reported before anything is changed, and if the grids are already identical nothing is done.

  • Crop Visible reduces the selected curves to the q range currently visible. It refuses to cut the middle out of a curve, and it refuses a selection in which some curves would be cropped on the left and others on the right.

  • Crop Zeros removes every point whose intensity is not positive. A confirmation dialog first points out that noisy data with occasional negative values are physically meaningful, being the difference between two positive and very close intensities — removing such points biases the remainder upwards. Use it only where a logarithmic display or an external program leaves no alternative.

  • Crop Left and Crop Right remove points one at a time from the respective end of each selected curve. They work in two stages: if the end point in question is not visible in the current zoom, the first press pans and resizes the zoom rectangle so that the outermost few points are shown, and prints press again to crop one point; each subsequent press removes one point. This lets you watch exactly what you are discarding at the beam stop or in the noise at high q.

  • Undo reverses the cropping operations one at a time, in reverse order. The undo history covers Crop Common, Crop Visible, Crop Left and Crop Right.

Any loaded curve that is modified by one of the cropping tools is added to the Produced Data list, so that the modified version can be saved without overwriting your original data unintentionally.

Produced Data and saving

Every curve created by the module — subtractions, divisions, joins, averages, normalizations and cropped copies — is added both to the Data files list, so it can be used as input to further operations, and to the Produced Data list below it. The directory to which produced curves will be written is shown above that list. It starts at the SOMO saxs directory and is then set to a subdirectory named produced under the directory you last loaded from, unless Lock is checked. Clicking on it opens a directory navigator, and the directory is created on the first save if it does not exist.

  • Select all selects the whole produced list.

  • Similar extends the selection to the curves whose names follow the same pattern as the first selected one — the whole family of subtractions from one parameter scan, for instance.

  • Save writes the selected produced curves as individual files, and is active only while some of them are still unsaved. Each is written with the name of the file it originated from, or the curve name with a .dat extension; existing files raise an overwrite prompt with an overwrite all option.

  • Save CSV writes all the selected produced curves into a single comma-separated file, whose name is derived from the common part of their names. If their q grids are not identical, versions cropped to the common grid are included in the output for compatibility, and a notice is issued.

  • Show adds the selected produced curves to the plot, and Show only displays them and nothing else.

  • Right-clicking an entry in the Produced Data list allows it to be renamed.

Individual files are written with a one-line header of the form

US-SOMO: SAXS: Data Utility output: name PSV:value I0se:value Conc:value Units:1/a

followed by a column-heading line and the data as q, I(q) and, when available, the standard deviation. The PSV, I0se and Conc fields appear only when those quantities are known, and are read back when the file is loaded again, here or elsewhere in US-SOMO.

Closing the window while produced curves remain unsaved raises a dialog listing them (up to fifteen by name) and offering to save them, to close anyway, or to cancel the close.

Concentrations and the companion dialogs

The Concentrations button opens the Solution Concentrations window, a table of every loaded curve and its concentration in mg/ml. The buffer and the blank are excluded, and the table is kept in step with the file list as curves are added, removed and created. Concentrations found in .dat file headers appear there automatically, and curves produced by the module inherit an appropriate value — the concentration of the solution for a subtraction, the mean for an average, 1 for a normalized curve. Concentrations are needed for the PSV route to α, for N and for Concentration normalized average, and are written into the header of each saved curve.

Values typed into that window take effect only once its Save values button has been pressed; a warning is issued if a calculation is started while edits are still pending. The window can be left open alongside this one.

The Data Utility has three companion dialogs, each with its own page in this manual:

  • Solution Concentrations — the concentration table itself, its copy and paste operations, and the loading and saving of .sbc concentration files.

  • File Concentration Loader — reached from Load in the above when the chosen file is not a .sbc file. It maps the columns of an arbitrary tabular file onto curve identifiers and concentrations, with a timecode adjustment and a trial match.

  • Select curves — reached from Select, for picking a subset out of a long list of curves by position, by name or by integrated intensity.

Naming conventions of the produced curves

The name of a produced curve records how it was made, so that a directory of results remains self-documenting. Decimal points are replaced by underscores, and a numeric suffix is appended if the name would otherwise collide with an existing one.

Buffer subtractionsolution_bsub_aalpha
Buffer dividesolution_bdiv_aalpha
Joinhigh-q-low-q_joffset-multiplier-cut

Notes and current limitations

  • The Best buffer subtraction button in the : Fitting window is not yet implemented and performs no action. Use Buffer subtraction over range and choose among the resulting curves.

  • The Guinier checkbox below the plot is not yet implemented. Guinier analysis is available in the SAS module I(q) panel; send the curves there with the S button.

  • In the current release the automatic Fit in the join, and the RMSD readout beside it, use the data from End upwards rather than the Start to End window. Until this is corrected, place End at the lower edge of the region you want fitted, or set the multiplier by hand with the wheel.

  • The Linear button in the join, which would fit an offset in addition to a multiplier, is currently disabled, in keeping with the caution against introducing a constant offset noted above.

  • The automatic Fit and the join itself require the two curves to share a common q grid over the fitted region; there is no interpolation. Where the two configurations were sampled differently, run Crop Common first.

  • Buffer subtraction, averaging and the related operations all require identical q grids, matched to within 5×10-6 A-1. The error message incompatible grids means either that the point counts differ or that the q values do; Crop Common resolves both.

  • Standard deviations are propagated only where all of the participating curves carry them. Since a single non-positive standard deviation causes the whole error column of a file to be discarded on loading, an unexpected NOT using standard deviation notice is usually traced back to that.
